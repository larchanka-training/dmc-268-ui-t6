# DESIGN_SYSTEM: Reviewer UI (Flat Console)

|                     |                                                                          |
| ------------------- | ------------------------------------------------------------------------ |
| Статус              | действующая система для экранов приложения                               |
| Где живёт код       | `src/shared/ui`                                                          |
| Где смотреть        | `pnpm storybook`: первая страница «Reviewer UI», затем этот документ     |
| Связанные документы | [`FRONTEND_ARCHITECTURE.md`](FRONTEND_ARCHITECTURE.md) (Ф-2, Ф-13, Ф-20) |

Этот документ нормативный. Он отвечает на вопрос «как должен выглядеть любой элемент интерфейса»,
в том числе тот, которого в приложении ещё нет. Если правило отсюда расходится с тем, что на
экране, ошибка на экране. Новый и изменяемый код следует этим правилам.

## 1. Главное правило

1. Базовые компоненты берутся из Ant Design в нашей теме и из `src/shared/ui`. На экране их не
   перекрашивают и не оформляют заново.
2. Составные компоненты под конкретный экран (таблица репозиториев, дерево действий, просмотр
   диффа) пишутся в `widgets` и `features` из базовых.
3. Если нужного компонента ещё нет, его сначала подгоняют по §9 и добавляют в Storybook, и только
   потом используют на экране.

Запрещено: задавать цвет, размер шрифта, радиус или высоту контрола числом в коде экрана (для
них есть тема и токены `--rv-*`); подключать компонент из другой библиотеки; менять вид компонента
Ant Design вне дизайн-системы. Отступы раскладки экрана пишутся числами из сетки §5.

Вид компонента Ant Design (цвет, шрифт, размер, радиус, рамка, внутренние отступы) меняется только
в `src/shared/ui`: токеном в `theme/buildTheme.ts`, правилом в `styles/antd.css` или в CSS-модуле
своего компонента-обёртки. В CSS-модуле экрана `:global(.ant-…)` допустим только чтобы разместить
компонент в раскладке этого экрана: внешний отступ, ширина, место в сетке.

Тема переключается параметром `mode` у `DesignSystemProvider` (`dark` или `light`). Провайдер сам
ставит `data-rv-theme` на корневой элемент. Тот же атрибут на любом элементе переключает токены
`--rv-*` внутри него: так один экран остаётся тёмным в светлой теме. Для компонентов
Ant Design нужен вложенный `ConfigProvider`, который сохраняет настройку движения внешней темы,
как в `src/pages/login/LoginPage.tsx`:

```tsx
// Пример компонента в src/pages/login/.
import { ConfigProvider, theme } from 'antd'
import type { JSX, PropsWithChildren } from 'react'

import { buildTheme } from '../../shared/ui'

export function DarkSection(props: PropsWithChildren): JSX.Element {
  const { token } = theme.useToken()
  return (
    <ConfigProvider theme={buildTheme('dark', { reducedMotion: !token.motion })}>
      <section data-rv-theme="dark">{props.children}</section>
    </ConfigProvider>
  )
}
```

`theme.useToken()` вызывается снаружи вложенного провайдера: при изменении системной настройки
он получает актуальный `token.motion` от внешнего `DesignSystemProvider`.

Ant Design пересчитывает исходные цвета своим алгоритмом (в тёмной теме затемняет акцент, фоны
статусов выводит сам). `buildTheme` добавляет второй алгоритм, который после штатного возвращает
цвета палитры, поэтому в любом компоненте цвета ровно те, что в §3.

В Storybook тема страницы документации берётся из актуального globals-события канала
(`.storybook/preview.tsx`); URL служит только начальным fallback. Возврат story → Docs
сохраняет тему, выбранную в toolbar.

Палитра записана дважды: `palette.ts` для темы и `tokens.css` для CSS. Их совпадение проверяет тест
`theme/buildTheme.test.ts`. Импорт из `src/shared/ui` подключает `tokens.css` и `antd.css`.

Заполненные `Tag` используют полупрозрачный цвет своего `tone`: 14% в тёмной теме и 11% в

это не готовый непрозрачный фон статуса из таблицы выше. Текст — смесь 85% `tone` и 15%
`--rv-text`, без прозрачности; исключение — `critical solid`: 70% `tone` и 30% `--rv-text`,
чтобы текст оставался доступным и на warning Alert при наведении на карточку.

и контраст обеих тем сохранены в [browser proof #127](plans/127-browser-proof.md).

`special` используется для decorator, annotation и regex. Для него выбран `purple8`: `purple7`
даёт 2.824:1 на тёмном insert-фоне `#132a2c`. Остальные цветные слоты используют шаг 7 палитры,
пересчитанный алгоритмом соответствующей темы. `punctuation` отдельно не перекрашивается.

`diffTheme.test.ts` проверяет реальные темы приложения с альфа-композицией: текст строк,
номера, выделения и edit-фрагменты — не ниже 4.5:1; дополнительно сохранена регрессионная
проверка синтаксиса с порогом 3:1 на обычном, insert- и delete-фоне. Эта дополнительная
проверка не заменяет общую норму контраста текста ниже.

Правила:

- Акцентный синий только у главного действия, ссылок, фокуса и включённых переключателей.
- Выбранное состояние (пункт меню, строка, страница в пагинации, сегмент) нейтральное, серое.
  Синяя заливка выбранного пункта запрещена.
- Цвет не единственный носитель смысла: рядом с цветной точкой всегда подпись.
- Значки, которые несут смысл или действуют (очистка поля, стрелка списка), контрастнее своего фона
  не меньше чем 3 к 1 (WCAG 1.4.11), кроме отключённых контролов.
- Контраст текста с фоном не ниже 4.5 к 1 в обеих темах. Это выполняется для всех цветов текста
  из таблицы на всех поверхностях из таблицы, для белого текста на акценте во всех трёх его
  состояниях и для подписи заполненного тега на его заливке. На «поверхности выбранной» лежит
  только основной и вторичный текст.

## 6. Глубина и рамки

- Поверхности плоские: без теней и без градиентов.
- Тень есть только у всплывающих слоёв (меню, список выбора, модальное окно). Она одна:
  мягкая тень и контур в 1px цветом заметной рамки (`--rv-pop-shadow`). Всплывающее
  `message` использует ту же тень через локальный `Message.boxShadow`; глобальная
  `boxShadowSecondary` сама по себе его не настраивает.
- Рамка нужна данным с чёткой границей: таблице, диффу, блоку метаданных. Заголовок страницы,
  кнопки, поиск и фильтры лежат прямо на странице, без карточки вокруг.

## 7. Состояния

| Состояние | Как выглядит                                                                                                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Наведение | фон `--rv-hover`; у обычной кнопки фон `#222737` (светлая `#ebeced`), рамка заметная, текст не меняется; у кнопки опасного действия с рамкой фон `--rv-danger-bg` (`#281d2b`, светлая `#fdecec`) |

| -------------------------- | ---------------------------------------------- | ----------------------------------------- |

| Опасная главная            | `#fa8a8a` / `#c52020`                          | `#e06060` / `#b01c1c`                     |
| Опасная текстовая          | `#281d2b` / `#fdecec`                          | `#1b1624` / `#fbd6d6`                     |
| Опасная обычная (с рамкой) | `#281d2b` / `#fdecec`                          | `#1b1624` / `#fbd6d6`                     |

Фон покоя опасной обычной кнопки тот же, что у обычной: `--rv-surface`. Ant Design не даёт для
него токенов, поэтому это одно правило в `styles/antd.css`; нажатие текстовой и опасной текстовой
кнопок задано токенами `colorFill` и `colorErrorBgActive` только у `Button`, чтобы не менять их
для остального приложения (дифф читает `colorErrorBgActive`).

ошибкой или предупреждением рамка остаётся красной или жёлтой, поэтому фокус показывает ореол
цвета `--rv-link`: у `Input` и `InputNumber` в обоих статусах это непрозрачный ореол 3px,
заданный через `errorActiveShadow` и `warningActiveShadow`. Обычный ореол поля — 3px цвета
focus-ring: `rgb(96 165 250 / 25%)` в тёмной теме, `rgb(29 78 216 / 20%)` в светлой.

У пагинации кольцо 2px применяется к фактическому месту фокуса: номер и jump — к `li`,
previous/next — к внутреннему `item-link`, когда фокус на `li`. В `CodeBlock` тот же 2px
`--rv-link` ring показывает клавиатурный фокус прокручиваемого блока. Явный `tabIndex` всем
коротким блокам не добавляется; горизонтальная прокрутка и её фокус проверяются в браузере.

`Segmented` при наведении использует `--rv-hover`, выбранный сегмент остаётся на
`--rv-surface-3`. Фокус выбранного radio виден и после стрелок, не только после Tab.

Переходы 150–200 мс. При системной настройке «уменьшить движение» провайдер отключает анимации
Ant Design, которыми управляет токен `motion` (мерцание `Skeleton active` к ним не относится), и следит за изменением настройки; пульс точки в `Tag` останавливается;
кольцо загрузки продолжает вращаться втрое медленнее, потому что остановленное кольцо выглядит как
зависшее.

Плавное появление и исчезновение длится 200 мс (`--rv-motion-fade`), только прозрачность: размер
и положение не меняются. Кривая зависит от направления: появляющееся замедляется
(`--rv-ease`), уходящее ускоряется (`--rv-ease-exit`, `cubic-bezier(0.4, 0, 1, 1)`). На уходе
замедляющаяся кривая отдаёт почти всё изменение первым 80 мс, и первый же тяжёлый кадр страницы
съедает их: кольцо гаснет скачком.

Кольцо ожидания страницы (`PageLoader`) показывается только после 300 мс непрерывного ожидания,
чтобы быстрая страница не мигала им, плавно появляется (`--rv-ease`) и плавно гаснет
(`--rv-ease-exit`), когда страница готова. Гаснуть оно начинает, когда страница уже нарисована
(через два кадра после конца ожидания), поэтому кольцо тает поверх страницы, а не исчезает вместе
с её первым тяжёлым кадром. Из страницы кольцо убирается, когда затухание закончилось (событие
`transitionend` по прозрачности самого слоя), а не по таймеру от начала затухания: на занятой
странице переход стартует с опозданием, и таймер обрезал бы его хвост. Запасной таймер в три
длины затухания (600 мс) не даёт кольцу зависнуть, если событие не пришло (скрытая вкладка,
прерванный переход). Кольцо, которое не успело стать видимым (ожидание кончилось раньше его
первого кадра), убирается сразу. Оно одно на приложение (кольца внутри контролов и таблиц остаются как
были), стоит в центре окна и не перехватывает клики. При «уменьшить движение» оно появляется и
исчезает сразу; 300 мс ожидания остаются, потому что это не движение.

Экран входа и экран обмена кода OAuth появляются так же: прозрачность от 0 до 1 за 200 мс, без
задержки; при «уменьшить движение» они видны сразу. Вложенный провайдер экрана входа берёт эту
настройку у внешнего.

## 8. Правила применения

**Кнопки.** На экране одна главная (`type="primary"`). Остальные обычные или `type="text"`.
`danger` только для действий, которые что-то прерывают или удаляют. Кнопке с одной иконкой
обязателен `aria-label`. Кнопка, которая на месте становится неактивной и должна сохранить фокус,
получает `aria-disabled` и класс из `useDisabledButtonClass` вместо `disabled` и остаётся без
`onClick`: нативно отключённая кнопка фокус теряет, а `aria-disabled` нажатие не отключает. Почему
класс — зависимость от внутренностей Ant Design, см. §11.

**Теги (`Tag` из `src/shared/ui`).**

| Вид                     | Когда                                                                         |
| ----------------------- | ----------------------------------------------------------------------------- |
| С точкой (по умолчанию) | всё, что сообщает состояние: статус прогона, важность high, medium, low, info |
| Заполненный (`solid`)   | только то, что требует действия: `critical` и блокирующий вердикт             |
| Контурный (`outline`)   | метаданные: ветка, движок, `summary-only`                                     |

Заполненных тегов на экране один-два.

Бейдж находки сохраняет точную подпись и отдельное оформление каждого уровня по
[решению #127](https://github.com/larchanka-training/dmc-268-ui-t6/issues/127#issuecomment-6291809919):

| Severity   | Подпись  | Тон Tag    | Вариант |
| ---------- | -------- | ---------- | ------- |
| `critical` | Critical | `critical` | `solid` |
| `high`     | High     | `critical` | `dot`   |
| `medium`   | Medium   | `high`     | `dot`   |
| `low`      | Low      | `warning`  | `dot`   |
| `info`     | Info     | `info`     | `dot`   |

Имя shared-тона `high` обозначает оранжевый цвет, а не одноимённый domain severity.
Это оформление отделено от фильтра «Критичность»: в нём остаются три группы D3 —
Critical = critical/high, Warning = medium/low, Info = info. Серверные verdict и counts
отображаются без пересчёта в UI.

**Выбор из вариантов.**

| Сколько вариантов                         | Компонент   |
| ----------------------------------------- | ----------- |
| Включено или выключено, применяется сразу | `Switch`    |
| Два-четыре вида одних и тех же данных     | `Segmented` |
| Несколько вариантов, все видны            | `Radio`     |
| Длинный список                            | `Select`    |

`Segmented` берётся из `src/shared/ui`, с обязательным осмысленным `aria-label`: например,
«Фильтр репозиториев» или «Вид диффа: src/a.ts». Обёртка передаёт публичный `tabIndex={-1}`
корню Ant Design; Tab останавливается один раз, на выбранном native radio. Стрелки меняют
значение и фокус, пропускают отключённые варианты и вызывают `onChange` один раз. Повторные
группы имеют отдельные native radio names. Controlled и uncontrolled варианты показаны в
Storybook; не добавлять экранную логику переписывания DOM или второй обработчик стрелок.

**Поля.** У каждого поля видимая подпись, плейсхолдер её не заменяет. Ошибка показывается под
своим полем.

**Навигация.** Боковое меню собирается из `Layout.Sider` и `NavMenu`. Кнопка-строка (`RowButton`)
там, где нажимается вся строка.

**Таблицы.** `DataTable` из `src/shared/ui`. Ячейки в одну строку, широкая таблица прокручивается
внутри своей рамки: при `nowrap=true` (по умолчанию) обёртка задаёт
`scroll.x='max-content'`, если `x` не указан. Явный `scroll.x` (число, строка или `false`)
сохраняется; `scroll.y` и другие настройки прокрутки сохраняются вместе с умолчанием.
`nowrap=false` разрешает перенос и не добавляет горизонтальную прокрутку; явный `scroll`
действует и в этом режиме. Внешняя рамка обрезает углы, прокручивается внутренний контейнер
таблицы. Примеры: `DataTable/Narrow`, `ExplicitScrollWidth` и `Wrapping` в Storybook. У каждого столбца есть доступное имя, включая колонку действий:
для настроек — «Настройки».

**Сообщения.** `Alert` внутри страницы. Всплывающее `message` только для короткого подтверждения
действия; ошибку, с которой надо что-то сделать, показывает `Alert`. Пустое состояние объясняет, что делать дальше, и даёт
кнопку. Пока данные грузятся, показываем `Skeleton` или кольцо загрузки (`Spinner`, его же
показывает `Spin`), а не пустоту. Ожидание всей страницы показывает кольцо `PageLoader`, и только
после 300 мс (§7).

## 9. Как подогнать новый компонент Ant Design

Порядок один и тот же для любого компонента, которого в приложении ещё не было.

1. Добавить историю в `src/shared/ui/stories` и открыть её в Storybook в обеих темах. Тема уже
   дала компоненту цвета, шрифт, радиус и высоту.
2. Сверить с разделами 3–7 по списку:
   - высота 26, 32 или 40px;
   - радиус по §5;
   - рамка 1px нужного цвета, без двойных рамок;
   - фон из списка поверхностей;
   - нет тени (кроме всплывающих слоёв) и нет градиента;
   - размеры текста из §4;
   - выбранное состояние нейтральное;
   - наведение, фокус и отключённое состояние по §7;
   - работает с клавиатуры, фокус виден.
3. Расхождение исправлять в таком порядке: сначала токен компонента в `buildTheme.ts`, и только
   если токена нет, правило в `styles/antd.css` с комментарием, зачем оно.
4. Если компоненту нужны одни и те же параметры на каждом экране, сделать обёртку в
   `src/shared/ui` (как `DataTable`).
5. В истории показать все состояния: обычное, наведение, фокус, отключено, ошибка или загрузка
   там, где они есть.
6. Добавить компонент в таблицу §10.

Чего делать нельзя: править вид нового компонента стилями на экране, где он понадобился.

## 11. Обновление Ant Design

`styles/antd.css` опирается на внутренние классы библиотеки. При обновлении Ant Design открыть
Storybook, пройти раздел «Ant Design» в обеих темах и поправить правила, которые перестали
действовать.

Кнопка, которая неактивна, но держит фокус («Отмена запрошена» в `RunControls`), получает
`aria-disabled` и класс отключённой кнопки antd из `useDisabledButtonClass` (`lib/`) вместо
`disabled`. Этот класс — не проп Button, а часть сгенерированных селекторов библиотеки: вид
отключённой кнопки и запрет наведения и нажатия antd даёт ему наравне с `:disabled`, а кольцо фокуса,
в отличие от `:disabled`, оставляет. `styles/antd.button.test.tsx` краснеет, если обновление это
меняет.

В Ant Design 6.6.5 override `lineWidthFocus` у `Input` и `Pagination` может оставить пустую
CSS-переменную вместо расширения кольца. Поэтому focus clear-icon Input и кольца Pagination
заданы узкими правилами в `antd.css`. При обновлении сначала перепроверить токен в реальном
DOM, затем actual focus targets и computed outline. `styles/antd.pagination.test.tsx`
проверяет достижимость селекторов для page, previous/next и обоих jump; браузерная проверка
подтверждает само кольцо в обеих темах.

У `Message` после обновления проверить именно тень `.ant-message-notice`; wrapper и title
её не рисуют. У `Segmented` перепроверить один Tab-стоп, Shift+Tab, native arrows,
пропуск disabled и ровно один `onChange` на нажатие, включая повторные группы.
Сохранение `tabIndex={-1}` на корне и наличия `aria-label` само по себе не доказывает
клавиатурное поведение.
