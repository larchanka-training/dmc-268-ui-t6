# DESIGN_SYSTEM: Reviewer UI (Flat Console)

|                     |                                                                          |
| ------------------- | ------------------------------------------------------------------------ |
| Статус              | действует; экраны приложения переводятся на неё по задаче #98            |
| Где живёт код       | `src/shared/ui`                                                          |
| Где смотреть        | `pnpm storybook`: первая страница «Reviewer UI», затем этот документ     |
| Связанные документы | [`FRONTEND_ARCHITECTURE.md`](FRONTEND_ARCHITECTURE.md) (Ф-2, Ф-13, Ф-20) |

Этот документ нормативный. Он отвечает на вопрос «как должен выглядеть любой элемент интерфейса»,
в том числе тот, которого в приложении ещё нет. Если правило отсюда расходится с тем, что на
экране, ошибка на экране. Экран, который ещё не переведён на дизайн-систему, правилам может не
соответствовать; новый и изменяемый код им следует.

## 1. Главное правило

1. Базовые компоненты берутся из Ant Design в нашей теме и из `src/shared/ui`. На экране их не
   перекрашивают и не оформляют заново.
2. Составные компоненты под конкретный экран (таблица репозиториев, дерево действий, просмотр
   диффа) пишутся в `widgets` и `features` из базовых.
3. Если нужного компонента ещё нет, его сначала подгоняют по §9 и добавляют в Storybook, и только
   потом используют на экране.

Запрещено: задавать цвет, размер шрифта, радиус или высоту контрола числом в коде экрана (для
них есть тема и токены `--rv-*`); подключать компонент из другой библиотеки; менять вид компонента
Ant Design вне дизайн-системы. Отступы раскладки экрана пишутся числами из сетки §5.

Вид компонента Ant Design (цвет, шрифт, размер, радиус, рамка, внутренние отступы) меняется только
в `src/shared/ui`: токеном в `theme/buildTheme.ts`, правилом в `styles/antd.css` или в CSS-модуле
своего компонента-обёртки. В CSS-модуле экрана `:global(.ant-…)` допустим только чтобы разместить
компонент в раскладке этого экрана: внешний отступ, ширина, место в сетке.

## 2. Как устроено

| Слой              | Файл                                           | Что делает                                        |
| ----------------- | ---------------------------------------------- | ------------------------------------------------- |
| Палитра           | `src/shared/ui/theme/palette.ts`               | Цвета обеих тем, один источник                    |
| Тема Ant Design   | `src/shared/ui/theme/buildTheme.ts`            | Всё, что настраивается токенами библиотеки        |
| Токены для CSS    | `src/shared/ui/styles/tokens.css`              | Те же значения как `--rv-*` для своих компонентов |
| Правки поверх Ant | `src/shared/ui/styles/antd.css`                | То, что токенами не выражается                    |
| Подключение       | `src/shared/ui/theme/DesignSystemProvider.tsx` | Включает всё перечисленное одним компонентом      |
| Свои компоненты   | `src/shared/ui/*`                              | перечислены ниже                                  |

Свои компоненты:

| Компонент       | Что это                                                                     |
| --------------- | --------------------------------------------------------------------------- |
| `Tag`           | тег состояния, важности и метаданных (§8)                                   |
| `Spinner`       | кольцо загрузки; его же показывает `Spin`                                   |
| `PageLoader`    | кольцо ожидания страницы: метка `PageLoading`, кольцо `PageLoaderHost`      |
| `PageHeader`    | заголовок страницы с описанием и действиями                                 |
| `DataTable`     | `Table` с умолчаниями системы                                               |
| `NavMenu`       | навигация бокового меню: `Menu` внутри `nav`, пункты являются ссылками      |
| `RowButton`     | текстовая кнопка во всю строку: шапка замечания, строка пользователя        |
| `TraceTree`     | `Tree` для журнала шагов: моноширинный, плотный                             |
| `ProgressSteps` | `Steps` для этапов процесса: одна отметка-кольцо на все состояния           |
| `CodeBlock`     | блок кода или JSON моноширинным шрифтом                                     |
| `Logo`          | знак Reviewer                                                               |
| иконки          | `IconRepositories`, `IconRuns`, `IconReview`, `IconSidebar`, `IconSettings` |

Тема переключается параметром `mode` у `DesignSystemProvider` (`dark` или `light`). Провайдер сам
ставит `data-rv-theme` на корневой элемент. Тот же атрибут на любом элементе переключает токены
`--rv-*` внутри него: так один экран остаётся тёмным в светлой теме (вместе с вложенным
`ConfigProvider theme={buildTheme('dark')}`).

Ant Design пересчитывает исходные цвета своим алгоритмом (в тёмной теме затемняет акцент, фоны
статусов выводит сам). `buildTheme` добавляет второй алгоритм, который после штатного возвращает
цвета палитры, поэтому в любом компоненте цвета ровно те, что в §3.

Палитра записана дважды: `palette.ts` для темы и `tokens.css` для CSS. Их совпадение проверяет тест
`theme/buildTheme.test.ts`. Импорт из `src/shared/ui` подключает `tokens.css` и `antd.css`.

Правила:

- Акцентный синий только у главного действия, ссылок, фокуса и включённых переключателей.
- Выбранное состояние (пункт меню, строка, страница в пагинации, сегмент) нейтральное, серое.
  Синяя заливка выбранного пункта запрещена.
- Цвет не единственный носитель смысла: рядом с цветной точкой всегда подпись.
- Значки, которые несут смысл или действуют (очистка поля, стрелка списка), контрастнее своего фона
  не меньше чем 3 к 1 (WCAG 1.4.11), кроме отключённых контролов.
- Контраст текста с фоном не ниже 4.5 к 1 в обеих темах. Это выполняется для всех цветов текста
  из таблицы на всех поверхностях из таблицы, для белого текста на акценте во всех трёх его
  состояниях и для подписи заполненного тега на его заливке. На «поверхности выбранной» лежит
  только основной и вторичный текст.

## 6. Глубина и рамки

- Поверхности плоские: без теней и без градиентов.
- Тень есть только у всплывающих слоёв (меню, список выбора, модальное окно). Она одна:
  мягкая тень и контур в 1px цветом заметной рамки (`--rv-pop-shadow`).
- Рамка нужна данным с чёткой границей: таблице, диффу, блоку метаданных. Заголовок страницы,
  кнопки, поиск и фильтры лежат прямо на странице, без карточки вокруг.

## 7. Состояния

| Состояние | Как выглядит                                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Наведение | фон `--rv-hover`; у обычной кнопки фон `#222737` (светлая `#ebeced`), рамка заметная, текст не меняется                                                                               |
| Нажатие   | на шаг темнее наведения: главная кнопка `#1d4fd0`, обычная `#2a3042` (светлая `#dfe2e6`); размер не меняется, волны при клике нет                                                     |
| Фокус     | кольцо 2px цветом `--rv-link` (в Ant Design это токен `colorPrimaryBorder`); у полей рамка `--rv-link` и ореол 3px                                                                    |
| Выбрано   | фон `--rv-selected`, текст `--rv-text`                                                                                                                                                |
| Отключено | как задаёт Ant Design: приглушённые текст и фон, курсор «недоступно»; рамка нейтральная `--rv-border-strong`, одна для Button, Input, InputNumber и Select; контрол остаётся на месте |
| Загрузка  | спиннер внутри контрола, контрол не исчезает                                                                                                                                          |
| Ошибка    | рамка `--rv-danger`, сообщение под полем                                                                                                                                              |

У полей фокус показывает рамка цвета `--rv-link`; ореол вокруг неё только дополняет её. У поля с
ошибкой или предупреждением рамка остаётся красной или жёлтой, поэтому фокус показывает ореол
цвета `--rv-link`.

Переходы 150–200 мс. При системной настройке «уменьшить движение» провайдер отключает анимации
Ant Design, которыми управляет токен `motion` (мерцание `Skeleton active` к ним не относится), и следит за изменением настройки; пульс точки в `Tag` останавливается;
кольцо загрузки продолжает вращаться втрое медленнее, потому что остановленное кольцо выглядит как
зависшее.

Плавное появление и исчезновение длится 200 мс (`--rv-motion-fade`, кривая `--rv-ease`), только
прозрачность: размер и положение не меняются. Кольцо ожидания страницы (`PageLoader`) показывается
только после 300 мс непрерывного ожидания, чтобы быстрая страница не мигала им, плавно
появляется и плавно гаснет, когда страница готова. Оно одно на приложение (кольца внутри
контролов и таблиц остаются как были), стоит в центре окна и не перехватывает клики. При
«уменьшить движение» оно появляется и исчезает сразу; 300 мс ожидания остаются, потому что это
не движение.

Экран входа и экран обмена кода OAuth появляются так же: прозрачность от 0 до 1 за 200 мс, без
задержки; при «уменьшить движение» они видны сразу. Вложенный провайдер экрана входа берёт эту
настройку у внешнего.

## 8. Правила применения

**Кнопки.** На экране одна главная (`type="primary"`). Остальные обычные или `type="text"`.
`danger` только для действий, которые что-то прерывают или удаляют. Кнопке с одной иконкой
обязателен `aria-label`.

**Теги (`Tag` из `src/shared/ui`).**

| Вид                     | Когда                                                                   |
| ----------------------- | ----------------------------------------------------------------------- |
| С точкой (по умолчанию) | всё, что сообщает состояние: статус прогона, важность high, medium, low |
| Заполненный (`solid`)   | только то, что требует действия: `critical` и блокирующий вердикт       |
| Контурный (`outline`)   | метаданные: ветка, движок, `summary-only`                               |

Заполненных тегов на экране один-два.

**Выбор из вариантов.**

| Сколько вариантов                         | Компонент   |
| ----------------------------------------- | ----------- |
| Включено или выключено, применяется сразу | `Switch`    |
| Два-четыре вида одних и тех же данных     | `Segmented` |
| Несколько вариантов, все видны            | `Radio`     |
| Длинный список                            | `Select`    |

**Поля.** У каждого поля видимая подпись, плейсхолдер её не заменяет. Ошибка показывается под
своим полем.

**Навигация.** Боковое меню собирается из `Layout.Sider` и `NavMenu`. Кнопка-строка (`RowButton`)
там, где нажимается вся строка.

**Таблицы.** `DataTable` из `src/shared/ui`. Ячейки в одну строку, широкая таблица прокручивается
внутри своей рамки.

**Сообщения.** `Alert` внутри страницы. Всплывающее `message` только для короткого подтверждения
действия; ошибку, с которой надо что-то сделать, показывает `Alert`. Пустое состояние объясняет, что делать дальше, и даёт
кнопку. Пока данные грузятся, показываем `Skeleton` или кольцо загрузки (`Spinner`, его же
показывает `Spin`), а не пустоту.

## 9. Как подогнать новый компонент Ant Design

Порядок один и тот же для любого компонента, которого в приложении ещё не было.

1. Добавить историю в `src/shared/ui/stories` и открыть её в Storybook в обеих темах. Тема уже
   дала компоненту цвета, шрифт, радиус и высоту.
2. Сверить с разделами 3–7 по списку:
   - высота 26, 32 или 40px;
   - радиус по §5;
   - рамка 1px нужного цвета, без двойных рамок;
   - фон из списка поверхностей;
   - нет тени (кроме всплывающих слоёв) и нет градиента;
   - размеры текста из §4;
   - выбранное состояние нейтральное;
   - наведение, фокус и отключённое состояние по §7;
   - работает с клавиатуры, фокус виден.
3. Расхождение исправлять в таком порядке: сначала токен компонента в `buildTheme.ts`, и только
   если токена нет, правило в `styles/antd.css` с комментарием, зачем оно.
4. Если компоненту нужны одни и те же параметры на каждом экране, сделать обёртку в
   `src/shared/ui` (как `DataTable`).
5. В истории показать все состояния: обычное, наведение, фокус, отключено, ошибка или загрузка
   там, где они есть.
6. Добавить компонент в таблицу §10.

Чего делать нельзя: править вид нового компонента стилями на экране, где он понадобился.

У каждого компонента из таблицы есть история в Storybook: в разделе «Ant Design» или, если у
него есть обёртка (`DataTable`, `NavMenu`, `TraceTree`, `ProgressSteps`, `PageLoader`), в разделе «Свои компоненты».
У `PageLoader` история с кнопкой, которая включает и выключает ожидание: приложение с моком
отвечает за 0 мс и кольцо почти не показывает, а в истории видны задержка, центр и оба перехода.

## 11. Обновление Ant Design

`styles/antd.css` опирается на внутренние классы библиотеки. При обновлении Ant Design открыть
Storybook, пройти раздел «Ant Design» в обеих темах и поправить правила, которые перестали
действовать.
