### Где текст задачи и код разошлись

Следовал коду и api#310, не выдуманной форме.

- В постановке координатора мерж Ч.2 ждал «часть 2» API. В ui#186 мерж ждёт Ч.1 и Ч.2 api#310: и `usage`, и `triggeredBy`. В плане так.
- «Новый параметр `status`» уже есть в OpenAPI, `RunListQuerySchema` и `runListEndpoint`. Новые вещи — контрол и то, что мок параметр применяет. `listMockRuns` фильтрует живой статус; неизвестное значение по-прежнему 422.
- `triggeredBy` в api#310 — логин или `null`. Объект с именем не предлагается. После выката `usage` — нули, не `null`. До staging оба поля в Zod необязательны, иначе ломается сегодняшний список.
- Ориентировочный `MetricsSummary` (`tiles`, `bucketStart`, `24h`) дашбордом не используется. Смысл плиток и рядов берётся из api#310. Имена JSON предлагает этот план. Страница не предлагает `24h`, схема ответа его принимает.
- «Незнакомый код как сейчас»: список код не показывает. Строка «Причина» и прогресс-бар на обновлённом main идут через `reasonText`, не через сырой код и не через девять фраз `errorReason`. Alert есть только у известных кодов карты.
- Средняя длительность дашборда — поле API (от создания до завершения `succeeded`). Длительность строки журнала — формула шапки от `startedAt`.
- Плитка вердикта показывает числа API по PR, клиент вердикт не считает. `null` — группа `noVerdict`, не `clean`.
- `publication_payload_too_large` нет в `_ERROR_TEXTS`. Текст взят из PIPELINE_SPEC §6: «Результат превышает лимит публикации VCS.» Каталог помечает код как ещё не записываемый. В карту он всё равно входит.
- Комментария про docs-site в теле ui#186 нет. Фаза документации взята из указания координатора: после выката, не в четырёх кодовых PR. Страницы docs-site на английском. В `roadmap.mdx` у пункта Dashboard нет бейджа Coming soon; `index.mdx` про этот дашборд не говорит и не правится.
