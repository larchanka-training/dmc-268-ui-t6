# План реализации: дашборд качества, журнал аудита и уведомления о лимитах (#186)

## Обзор

Задача [ui#186](https://github.com/larchanka-training/dmc-268-ui-t6/issues/186): участник команды или владелец репозитория видит понятную причину, когда ревью упёрлось в лимит, журнал запусков (кто запустил, токены, стоимость) и дашборд по уже сохранённым прогонам.

Четыре части — четыре PR. Сливать их в один PR нельзя. К первой сдаче 31.10.2026 ожидается только Ч.1. Ч.2 мержится после того, как на staging окажутся Ч.1 и Ч.2 [api#310](https://github.com/larchanka-training/dmc-268-api-t6/issues/310) (`usage` и `triggeredBy`). Ч.3 мержится после Ч.3 api#310 (`GET /api/metrics/summary`). До этого Ч.2 и Ч.3 пишутся на моке. Ч.4 не начинается, пока техлид не опубликует каталог новых кодов лимитов спринта 4.

Статус плана: ожидает утверждения. Код по этому плану не писался.

Ветки от `main`, по одной на часть: `feat/186-analytics-audit-reasons`, `feat/186-analytics-audit-log`, `feat/186-analytics-audit-dashboard`, `feat/186-analytics-audit-limits`. Документация после выката — отдельная ветка `docs/186-analytics-audit`. В теле каждого PR: `Refs #186`, без закрывающего слова (`Fixes` / `Closes`). Заголовок PR — conventional, не длиннее 72 символов.

## Что уже есть в коде

Проверено по текущим деревьям `dmc-268-ui-t6` и `dmc-268-api-t6`.

- `RunSessionSchema` — `z.object` (`src/entities/run/model/schemas.ts`). Неизвестные ключи отбрасываются, это зафиксировано в `docs/FRONTEND_ARCHITECTURE.md` §4. Обязательные поля списка сегодня: `id`, `engine`, `model`, `status`, `trigger`, `createdAt`, `startedAt`, `finishedAt`, `attempt`, `cancelRequested`, `summaryOnly`, `pullRequest`, `actionCount`, `errorCode`. Полей `triggeredBy` и `usage` нет ни в Zod, ни в OpenAPI `RunSession`.
- `RunDetailSchema` уже требует `budget: RunBudgetSchema | null` (`tokensIn`, `tokensOut`, `costUsd`, `tokenLimit`, `costLimitUsd`). Шапка `RunHeader` бюджет не рисует.
- `errorCode` на странице — сырой код: строка «Ошибка» в `RunHeader` и подпись этапа в `RunProgressBar`. Для `skipped` прогресс-бар не строится (`runProgress` возвращает `null`), поэтому `budget_paused` на странице виден только в шапке.
- Список `/runs` (`RunsPage`) колонок причины не показывает. Фильтр URL — только `repo` (`src/features/run-list-filter`). Курсор живёт в `useInfiniteQuery`, не в адресе. Размер страницы — `RUN_LIST_PAGE_SIZE` = 20.
- Параметр `status` у `GET /api/runs` уже есть: OpenAPI, `RunListQuerySchema`, `runListEndpoint`. `useRunList` его не передаёт. Мок `listMockRuns` параметр разбирает и при фильтрации игнорирует.
- Маршруты (`src/app/routes.tsx`): `/repositories`, `/repositories/:repoId/settings`, `/runs`, `/runs/:runId`, `/review`. Пункты меню (`AppSidebar`): «Репозитории», «Прогоны», в моке ещё «Ревью».
- `GET /api/metrics/summary` в OpenAPI помечен `x-status: planned`. Форма `MetricsSummary` ориентировочная: `range` = `24h | 7d | 30d`, `tiles` — произвольные числа, `series[]` — `bucketStart` и произвольные числа. Роута в приложении нет. В `package.json` библиотеки графиков нет.
- `Workspace` в OpenAPI и `WorkspaceSchema` — `id`, `name`, `installationId`. Дневной бюджет в этом DTO нет. В БД он есть: `workspaces.daily_budget_usd`. Паузу считает воркер: лимит `0` значит «лимит не задан»; при положительном лимите прогон становится `skipped` / `budget_paused`, когда остаток меньше `FAST_RUN_COST_LIMIT` = `$0.50` (`handle_review_run.py`). UI этот порог не считает.
- Образец «код → текст» — `errorReason` в `src/features/repository-settings/lib/ragIndexView.ts`: своя карта, поиск только по `Object.keys`, неизвестный код не угадывается, `constructor` не считается известным. Слой `features` виджету недоступен, поэтому карта прогона живёт в `entities/run`, а приём копируется.
- Фикстуры мока с префиксами `11111111-1111-4111-8111`, `22222222-2222-4222-8222`, `33333333-3333-4333-8333` лежат в `src/app/mocks`. Прод подключает мок динамическим импортом из `src/main.tsx`. `scripts/verify-prod-bundle.sh` падает, если эти префиксы попали в `dist/assets/*.js`.
- Пользовательские страницы `docs-site/content/docs/` написаны по-английски. В `roadmap.mdx` пункт дашборда стоит в разделе Dashboard и бейджа Coming soon не имеет. В `index.mdx` блок Coming soon про дашборд не говорит.

## Тексты причин Ч.1

Источник восьми кодов — `_ERROR_TEXTS` в `app/modules/reviews/application/check_runs.py`. Меняется файл в api — меняются строки здесь. Копировать дословно.

| `errorCode`                      | Текст                                                                    |
| -------------------------------- | ------------------------------------------------------------------------ |
| `budget_paused`                  | Дневной бюджет исчерпан, ревью на паузе.                                 |
| `budget_exceeded`                | Превышен лимит стоимости прогона.                                        |
| `deadline_exceeded`              | Прогон не уложился в лимит времени.                                      |
| `llm_context_overflow`           | PR не помещается в контекст модели.                                      |
| `llm_rate_limited`               | Провайдер модели ограничил частоту запросов. Перезапустите прогон позже. |
| `verification_budget_exceeded`   | Бюджета недостаточно для обязательной проверки.                          |
| `verification_deadline_exceeded` | Недостаточно времени для обязательной проверки.                          |
| `verification_context_overflow`  | Обязательные данные проверки не помещаются в контекст.                   |

`publication_payload_too_large` в `_ERROR_TEXTS` нет. Текст — каталог `docs/PIPELINE_SPEC.md` §6: «Результат превышает лимит публикации VCS.» В той же строке каталога код помечен «цель #107, код пока не пишет». UI текст всё равно заводит: когда код появится, страница уже умеет его показать.

`policy_*` не переводятся (api#204). Остальные коды `_ERROR_TEXTS`, которых нет в таблице, в Ч.1 тоже не переводятся: неизвестный код остаётся сырым.

Короткий текст в списке — та же фраза, без кода рядом. На странице прогона код стоит рядом с фразой.

Alert summary-only не входит в карту. Сейчас это `RunDiff`: заголовок «Дифф слишком большой», описание «Больше 3 000 строк — показан только список файлов, построчного ревью нет.» Отдельная серая строка шапки «Summary-only прогон (дифф > 3000 строк)» тоже остаётся. Ч.4, если размер так и означает summary-only, меняет одну константу заголовка, а не вёрстку `RunDiff`.

Текст паузы на дашборде другой и в карту не кладётся: «Дневной бюджет исчерпан, ревью на паузе до 00:00 UTC». Его отдаёт признак `paused` сводки, не `errorCode`.

## Контракт, который UI отдаёт api#310

api#310 уже называет смысл полей и говорит, что имена согласуются с исполнителем UI до мержа. Ориентировочный `MetricsSummary` в OpenAPI дашбордом не считается: его заменяет форма ниже, когда снимут `x-status: planned`. Пока Ч.3 api#310 не влита, это предложение, а не действующий провод.

`usage` и `triggeredBy` на `RunSession` (список, деталь, ответы cancel/rerun — везде, где тело есть `RunSession`):

```ts
usage: { tokensIn: int >= 0, tokensOut: int >= 0, costUsd: number >= 0 }
triggeredBy: string | null   // логин GitHub, не объект
```

Смысл, уже записанный в api#310:

- `usage` — сумма `usage_events` по всем попыткам и совпадает с расходной частью `budget` того же прогона. Записей нет — нули, не `null`.
- `triggeredBy` — логин того, чьё действие в PR сделало head пригодным к ревью (push / `synchronize`, лейбл `ai-review`, `reopened`), либо логин пользователя портала при `POST /api/runs/{id}/rerun`. Завершение CI и sweep инициатором не считаются. Старый прогон и неизвестный инициатор — `null`. Бот — тоже инициатор.
- До staging поля в Zod необязательные: ответ сегодняшнего `GET /api/runs` без них обязан разбираться. На мерже UI, когда обе части api#310 уже на staging, `usage` становится обязательным объектом (не nullable), `triggeredBy` — обязательным `string | null`. Иначе `tests/test_ui_zod_contracts.py` в api не сойдётся поле в поле (`required`, nullable, набор ключей).

`GET /api/metrics/summary`. Query, как в api#310: `range` = `24h | 7d | 30d`, необязательный `repo` (full name, 1..512, как у списка прогонов). Чужой `repo` — пустая сводка, не ошибка и не чужие числа. Видимость та же, что у `GET /api/runs`.

Страница шлёт только `7d` и `30d`. Значение `24h` остаётся в схеме ответа, чтобы снимок не расходился с enum api#310; контрола «24 часа» нет. Нет `range` в адресе — это `7d`.

Тело, закрытый объект (`additionalProperties: false`):

```ts
MetricsSummary = {
  range: '24h' | '7d' | '30d',
  runsByStatus: { succeeded, failed, cancelled, skipped }, // int >= 0, только итоговые
  pullsByVerdict: { blocking, attention, clean, noVerdict }, // int >= 0
  findingsBySeverity: { critical, high, medium, low, info },
  findingsByCategory: { security, correctness, performance, readability },
  averageDurationMs: number | null, // нет succeeded — null
  tokensIn: int >= 0,
  tokensOut: int >= 0,
  costUsd: number >= 0,
  series: Array<{
    day: string, // календарный день UTC, YYYY-MM-DD
    findings: { security, correctness, performance, readability },
    runCount: int >= 0,
    averageDurationMs: number >= 0, // день без данных — 0
    costUsd: number >= 0,
  }>,
  workspaces: Array<{
    name: string, // minLength 1
    dailyBudgetUsd: number >= 0, // 0 — лимит не задан
    spentTodayUsd: number >= 0,  // сутки UTC
    paused: boolean,
  }>,
}
```

Что UI не пересчитывает:

- вердикт и группа `noVerdict` — числа API; `null` не складывается в `clean`; зерно — PR по вердикту последнего завершённого прогона в периоде, тем же правилом `run_verdict`, что список PR репозитория (api#310);
- средняя длительность дашборда — от `createdAt` до `finishedAt` у `succeeded`, как в api#310;
- `paused` — флаг API, то же правило, что `budget_paused` у воркера; UI не сравнивает остаток с `$0.50` и не с нулём;
- дневной бюджет — USD на Workspace, не токены.

Активные прогоны (`queued`, `running`, `publishing`) в `runsByStatus` не входят: итогового статуса у них нет. `runCount` в ряде UI на график не выводит, но в схеме оставляет: api#310 просит число прогонов по дням. Стоимость дня тоже остаётся в ряде; плитка периода берёт верхний `costUsd`.

Пустая сводка (все четыре итоговых статуса — 0) — пустое состояние страницы, без осей. Нулевые дни, которые API присылает «днями без данных», в этом случае не рисуются. Блок «Бюджет на сегодня» от периода не зависит и остаётся, если `workspaces` не пуст.

`Workspace` и `Me` не расширяются: обязательное поле сломало бы `GET /api/auth/me`.

## Решения

1. **Карта причин одна.** `errorReason(code): string | null` в `src/entities/run/lib/errorReason.ts`, экспорт из `entities/run`. Поиск как в `ragIndexView`: только собственные ключи карты. `null` — текста нет. Ч.4 добавляет строки в эту карту и тесты, а не новый рендер.
2. **Где текст на странице прогона.** Известный код — `Alert` в `RunHeader` (antd, уже в дизайн-системе): фраза и сырой код рядом. `failed` — `type="error"`, `skipped` и `cancelled` — `type="warning"`. Неизвестный код — Alert причины нет. Строка «Ошибка» и подпись прогресс-бара по-прежнему показывают сырой код. Бар для `skipped` не появляется.
3. **Список.** Рядом со статусом — фраза без кода. Неизвестный код и `errorCode: null` список не меняют: сегодня код там не рисуется.
4. **Тип запуска в журнале — `trigger`.** В фоне ui#186 «тип запуска» — это то, что шапка показывает только для `rerun`, а не движок. Колонка печатает значение enum (`webhook`, `manual`, `rerun`, `dry_run`), как список печатает статус. Движок в журнале не дублируется.
5. **Длительность строки журнала** — та же, что у шапки: `startedAt` → `finishedAt` или «сейчас», нет `startedAt` — «—». Это не средняя длительность дашборда.
6. **Расход списка — `usage`, расход шапки — `budget`.** Нет поля `usage` (старый ответ) и нули — на экране 0 токенов и `$0`. `budget: null` в шапке — «—» и у расхода, и у лимитов: объекта лимитов нет, подставлять нули нельзя. Лимиты только читаются.
7. **Фильтр репозитория на `/audit` как на `/runs`:** параметр `repo`, плашка и «Сбросить фильтр», без нового выпадающего списка. Статус — новый `Select` («все» или одно из семи значений `RunStatus`), параметр `status`. Смена фильтра меняет ключ `useInfiniteQuery`, курсор начинается заново. Курсор в URL не пишется.
8. **Ключ списка** становится `{ repo: repo ?? null, status: status ?? null }`. Префикс `['runs', 'list']` по-прежнему сбрасывает и `/runs`, и `/audit`.
9. **Графики без новой зависимости.** Два графика на SVG в странице аналитики. Цвета серий — `var(--rv-critical)`, `var(--rv-high)`, `var(--rv-warning)`, `var(--rv-link)` (Security, Bug, Performance, Style). Линия длительности — `var(--rv-accent)`. Hex в странице нет. Решение о библиотеке не окончательное: см. открытые вопросы. Если библиотека всё же появится, строка в теле PR и коммит lockfile обязательны (AGENTS.md).
10. **Фикстуры аналитики** только под `src/app/mocks`, импорт из `mockTransport`. В них нет префиксов id, которые ловит `verify-prod-bundle`. Страница `pages/analytics` мок не импортирует.
11. **Документация пользователя не входит в четыре PR кода.** Комментарий к задаче: после выката обновить `roadmap.mdx` (раздел Dashboard, снять формулировку «скоро», если она есть), описать дашборд, журнал и уведомления в `features.mdx`, добавить мокапы. `index.mdx` и `how-it-works.mdx` не трогать. `features.mdx` — ядерная страница: в ревью фраза «`features.mdx` прочитана целиком». Текст docs-site — английский, как соседние страницы. Каждый кодовый PR в `Refs` указывает эту отложенную работу и docs-site не меняет.
12. **Новые строки UI — русский**, как остальной интерфейс. Переключатель языка (#182) их не ждёт.
13. **Иконки пунктов** — того же тонкого штриха, что `IconRuns` (`src/shared/ui/icons/icons.tsx`). Готового значка такого веса в меню нет.

## Открытые вопросы

1. **Лимиты только для чтения.** Рекомендация плана: да, контролов изменения нет — ни дневного бюджета, ни лимитов прогона. Так написано во вне scope ui#186 и api#310. Нужно подтверждение человека.
2. **Библиотека графиков.** В зависимостях её нет. Рекомендация: не добавлять, рисовать SVG цветами `--rv-*`. Это не окончательное решение. Если нужен пакет, кандидат под antd — отдельное согласованное имя; в план оно не зашито. Появление пакета — строка в теле PR.
3. **Необязательные поля и снимок Zod.** До staging `usage` и `triggeredBy` необязательны. На мерже они должны совпасть с OpenAPI (`usage` обязателен и не `null`, `triggeredBy` обязателен и nullable). Кто пинит коммит UI в `tests/test_ui_zod_contracts.py` и в каком порядке ужесточается `required`, надо согласовать с исполнителем api#310 до мержа.
4. **Имена полей `MetricsSummary`.** Смысл фиксирует api#310, имена в теле этого плана — предложение UI (в том числе `noVerdict`, `day`, `workspaces`). Мерж Ч.3 с обеих сторон — после того, как исполнитель API эти имена принял.
5. **Ревью `features.mdx`.** Страница ядерная. В Submit review нужна дословная фраза «`features.mdx` прочитана целиком» от техлида или назначенного им человека. Кто пишет фразу — вопрос к человеку, не к автору docs-PR.
