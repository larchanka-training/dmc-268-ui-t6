## Решения

- В `idle` визуального слота нет. Слот занимает одинаковое место в `waiting`
  с GET, пустых промежутках между GET и `timedOut`, включая ручной GET.
  Новый вход после OAuth с ready intent может иметь другой начальный layout,
  чем отдельный обычный визит idle; статус фиксируется при mount и не переключается
  из idle в waiting в рамках той же страницы.
  Начальный размер резерва — 32 px на широком экране и 56 px при ширине
  до 575 px. Это размеры раскладки из сетки 4 px (§5 дизайн-системы),
  достаточные для обычной строки и двух строк с кнопкой `small` (26 px).
  Старый `margin-bottom: 8px` не возвращать: текущий grid уже задаёт 18 px.
  Итоговую достаточность резерва подтвердить измерением всех состояний.
- Цвета, типографика, спиннер и кнопка остаются из Flat Console. Изменение
  ограничено раскладкой и объявлением статуса; анимация размеров не нужна.
- Постоянный DOM-узел сам по себе не доказывает постоянный узел accessibility
  tree. Регион `role="status"`, `aria-atomic="true"` не скрывать через
  `display: none`, `visibility: hidden`, `hidden` или `aria-hidden`.
  Первое сообщение должно обновить уже зарегистрированный пустой регион.
  При необходимости применить минимальную отдельную презентационную
  синхронизацию объявления, без изменения хука опроса и без производного
  React state в effect. Проверить начальный GET, а не только следующий тик.
- Проверить также ветку ошибки без данных: сейчас `RepositoriesPage` может
  убрать весь `RepositoryList` в idle. Если она нарушает AC «пока открыта
  страница», закрепить единственный постоянный live region на уровне страницы,
  оставив визуальный резерв в виджете. Не создавать два озвучивающих региона
  и не раскрывать пустую таблицу при ошибке только ради сохранения региона.

## Срез 2: работоспособность строки во время опроса

**Результат:** заменить проверки отсутствия `disabled` / `aria-disabled`
наблюдаемыми действиями в `src/pages/repositories/RepositoriesPage.test.tsx`.

**AC:** при отложенном GET в активном окне опроса клик переключателя
реально вызывает PATCH нужного id с `{ enabled: false }`, меняет
`aria-checked`, после ответа сохраняет подтверждённое значение. Настройки
этой же строки открывают нужный диалог на текущем main; после #106 тест
использует настоящий роутер и проверяет переход и содержимое нужного экрана.
Клик и отсутствие атрибута сами по себе не считаются доказательством.

**Проверка мутациями:** по отдельности временно заблокировать переключатель
и настройки именно при GET/опросе. Для кнопки — `disabled` или убрать
обработчик; для ссылки — запретить переход/убрать корректный href, поскольку
один `aria-disabled` не блокирует навигацию. Каждый мутант должен дать
красный тест своей функциональности. Записать команду и упавшее утверждение,
откатить каждую мутацию, повторить зелёный запуск. Не коммитить мутантов.
Сохранить ожидание disabled только для собственной незавершённой PATCH.

**Зависимость:** подготовка и актуальная форма настроек после координации.
**Размер:** S, 1 тестовый файл (при необходимости соседний widget-тест).

## Браузерные доказательства для PR

Два разных сценария, реальная страница/shell/Query-хуки, production polling без правок;
mock mode выключен, GET/PATCH перехвачены только на HTTP-границе.

1. **Геометрия с заполненным fixture.** Осознанно засеять `['repos']` известным списком,
   сохранить данные/sidebar при сравнении. Ordinary idle — свежая страница/context без
   ready intent; polling entry — отдельный свежий mount с ready intent. На 1280×900 и
   390×900 в обеих темах измерить поиск/рамку таблицы/слот: первый held GET, интервал,
   следующий held GET, второй интервал, таймаут, ручной held GET. Ожидание: 0 px внутри
   ожидания (допуск округления максимум 1 px), резерв 32/56 px. Idle сравнить с ordinary
   layout текущего main отдельно: в нём нет пустого блока. Не называть seeded fixture
   входом без данных. На 390 px ширина документа равна viewport, timeout/action помещаются.
2. **Первый вход и ошибка без кэша.** Свежий QueryClient/context, `['repos']` не засеян.
   Ready intent перед mount (либо настоящий `/auth/callback` с контролируемым OAuth
   ответом, только если фактически пройден). Удержать первый GET, наблюдать один DOM/AX
   backend node сначала пустым, затем заполненным после двух кадров. В другом свежем
   context без intent отклонить первый GET: status сохраняется при скрытом списке.
   Проверить non-ignored status, live=polite, atomic=true и отсутствие hidden/inert
   у предков. При route-входе дождаться исчезновения PageLoader; прямой harness не
   монтирует его и проверяет видимость своих предков. Прямой ready-intent mount не
   выдавать за полный OAuth-путь.

Фактический follow-up QA использовал direct-ready harness с реальными page/shell/Query
и HTTP interception, без route PageLoader и auth init. Seeded geometry и no-cache
AX/error cases выполнены отдельно, итоговая матрица — [todo](120-todo.md). Bonus callback
попытка не дала пригодного evidence (paused clock/lazy route mount) и не входит в приёмку.

Для timing policy дополнительно ответить на один GET намеренно быстро: сообщение может
быть отменено до назначения. Held GET должен допустить два кадра и появление текста.
Это не утверждение, что каждый GET озвучен: каждый достаточно медленный GET может повторить
сообщение (примерно до 24 за 120 с). Сохраняются existing cancellation/first-delayed-GET
тесты и два отменяемых rAF. Реальная речь первого сообщения и таймаута остаётся отдельным
незакрытым AC до наблюдения browser/AT; DOM/AX не заменяют речь. Проверить клавиатуру,
видимый фокус, действие таймаута и reduced motion в обеих темах.

Follow-up добавлять логическими commit groups: `fix` (слот, resolver, CSS и widget/helper
тесты), `test` (строгая идентичность page status, exact key mutant), `docs` (Ф-22,
план/todo/evidence). Опубликованную первоначальную историю ради дробления не переписывать.
