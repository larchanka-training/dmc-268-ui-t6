## Решения

- Слот остаётся частью раскладки и занимает одинаковое место в `idle`,
  `waiting` с GET, между GET и `timedOut`. Убрать скрытие пустого слота.
  Начальный размер резерва — 32 px на широком экране и 56 px при ширине
  до 575 px. Это размеры раскладки из сетки 4 px (§5 дизайн-системы),
  достаточные для обычной строки и двух строк с кнопкой `small` (26 px).
  Старый `margin-bottom: 8px` не возвращать: текущий grid уже задаёт 18 px.
  Итоговую достаточность резерва подтвердить измерением всех состояний.
- Цвета, типографика, спиннер и кнопка остаются из Flat Console. Изменение
  ограничено раскладкой и объявлением статуса; анимация размеров не нужна.
- Постоянный DOM-узел сам по себе не доказывает постоянный узел accessibility
  tree. Регион `role="status"`, `aria-atomic="true"` не скрывать через
  `display: none`, `visibility: hidden`, `hidden` или `aria-hidden`.
  Первое сообщение должно обновить уже зарегистрированный пустой регион.
  При необходимости применить минимальную отдельную презентационную
  синхронизацию объявления, без изменения хука опроса и без производного
  React state в effect. Проверить начальный GET, а не только следующий тик.
- Проверить также ветку ошибки без данных: сейчас `RepositoriesPage` может
  убрать весь `RepositoryList` в idle. Если она нарушает AC «пока открыта
  страница», закрепить единственный постоянный live region на уровне страницы,
  оставив визуальный резерв в виджете. Не создавать два озвучивающих региона
  и не раскрывать пустую таблицу при ошибке только ради сохранения региона.

## Срез 1: постоянная геометрия и доступный статус

**Результат:** поиск и рамка таблицы остаются на месте, ожидание и таймаут
доступны assistive technology с первого запроса.

**Файлы:** `src/widgets/repository-list/ui/RepositoryList.module.css`,
`src/widgets/repository-list/ui/RepositoryList.tsx`,
`src/widgets/repository-list/ui/RepositoryList.test.tsx`; при необходимости
`src/pages/repositories/RepositoriesPage.tsx` и его тест (максимум 5 файлов).

**AC:** постоянный резерв во всех состояниях; один живущий со страницей
status; существующая видимость текста только во время GET и при таймауте
сохранена. Тесты проверяют содержимое, идентичность узла при rerender и
переходы состояний, но не заявляют проверку CSS или озвучивания.

**Проверка:** воспроизвести дефект до исправления в настоящем браузере;
после — выполнить матрицу ниже и профильные регрессии #92.
**Зависимость:** подготовка. **Размер:** M, 3–5 файлов.

## Срез 2: работоспособность строки во время опроса

**Результат:** заменить проверки отсутствия `disabled` / `aria-disabled`
наблюдаемыми действиями в `src/pages/repositories/RepositoriesPage.test.tsx`.

**AC:** при отложенном GET в активном окне опроса клик переключателя
реально вызывает PATCH нужного id с `{ enabled: false }`, меняет
`aria-checked`, после ответа сохраняет подтверждённое значение. Настройки
этой же строки открывают нужный диалог на текущем main; после #106 тест
использует настоящий роутер и проверяет переход и содержимое нужного экрана.
Клик и отсутствие атрибута сами по себе не считаются доказательством.

**Проверка мутациями:** по отдельности временно заблокировать переключатель
и настройки именно при GET/опросе. Для кнопки — `disabled` или убрать
обработчик; для ссылки — запретить переход/убрать корректный href, поскольку
один `aria-disabled` не блокирует навигацию. Каждый мутант должен дать
красный тест своей функциональности. Записать команду и упавшее утверждение,
откатить каждую мутацию, повторить зелёный запуск. Не коммитить мутантов.
Сохранить ожидание disabled только для собственной незавершённой PATCH.

**Зависимость:** подготовка и актуальная форма настроек после координации.
**Размер:** S, 1 тестовый файл (при необходимости соседний widget-тест).

## Браузерные доказательства для PR

Настоящий браузер, mock mode, известная заполненная таблица; задерживать
GET управляемым mock/interception, не менять production polling ради QA.
Одинаковые данные и состояние sidebar при сравнении. Ширины 1280 и 390 px,
светлая и тёмная темы. Для каждой комбинации записать viewport, браузер,
состояние, координаты `getBoundingClientRect().top` поля поиска и рамки
таблицы, высоту слота: idle → первый pending GET → промежуток → второй GET
→ промежуток → timedOut → ручной GET. Ожидание: смещение 0 px (допуск только
явно записанного субпиксельного округления, максимум 1 px). Не подменять
сдвиг геометрии изменением числа строк. На 390 px нет прокрутки документа,
прокрутка таблицы остаётся внутри её рамки.

В Accessibility tree проверить один status до первого сообщения, с текстом,
между GET, после таймаута, при ошибке без данных. Отдельно подтвердить
первое «Загрузка репозиториев» настоящим скринридером (например VoiceOver
в поддерживаемом браузере), зафиксировать связку и наблюдаемую речь.
Accessibility tree и DOM-тест доказывают доступность узла, но не факт речи.
Если инструмента/оператора нет, прямо указать непроверенную часть и оставить
AC открытым; не заменять доказательство предположением. Проверить объявление
таймаута, отсутствие озвучивания спиннера, клавиатуру, видимый фокус,
работоспособность кнопки таймаута и reduced motion в рамках изменённого UI.

## Завершение и риски

После реализации запустить все шесть gates: `pnpm lint`,
`pnpm check-types`, `pnpm format:check`, `pnpm test`, `pnpm build`, затем
`pnpm verify:prod-bundle` именно по свежему production build. Проверить
отсутствие изменений polling/auth/API и случайных файлов #110/#114–116.
В PR: What / Why / How to verify / Refs; таблица геометрии, browser/AT
доказательства, две тестовые мутации и результаты команд; `Refs #120`, без
closing keywords. Review текущего head и разрешение тредов — по workflow.

Основные риски: пересечение PR, недостаточный мобильный резерв, первое
объявление одновременно с монтированием, условный unmount при ошибке,
ложная проверка jsdom. Меры перечислены выше. Объём — три связанных среза;
параллельная правка общих файлов не нужна. Вопросов по продукту, мешающих
начать после одобрения плана, нет. Доступность реального screen-reader QA
проверить в начале разработки. На этапе планирования gates не запускались.
