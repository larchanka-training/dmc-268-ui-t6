## Repository settings

Open **Repositories** in the dashboard and click the gear next to a repository. Form changes
apply to the next run.

<RepositorySettingsMock />

| Setting | What it does |
| --- | --- |
| **Automatic review** | Turns reviews on or off for the repository. Today a pull request still needs the `ai-review` label. Saved at once. <StatusBadge /> Soon: on reviews every pull request automatically, off reviews only pull requests with the label. |
| **RAG** | Builds a code index of the repository, see [Code index](#code-index-rag). Saved at once. |
| **CI waiting** | Auto, Always or Never, see [CI waiting](/docs/how-it-works#ci-waiting). |
| **Comment limit** | How many findings are posted as inline comments, from 1 to 10. The rest go to the review body. |
| **Verdict** | "Comment" posts every review as a comment. "Request changes" posts blocking reviews as Request changes. |
| **Branch filter** | Target branch masks, one per line, for example `main` or `release/*`. Empty means every branch. Up to 20 masks. |
| **Severity threshold** | `All` posts every level. `Warn & Crit` drops `info`. `Only Critical` keeps `critical` and `high`. |

In a branch mask, `*` matches within one part of the name and `**` also crosses `/`. The
characters `? [ ] { } ! \ ~ ^ :` are not allowed. A pull request to a branch outside the filter
is skipped.

Findings below the severity threshold are not posted; the `AI Review` check says how many were
hidden.

Below the form, **Review rules** shows the status of your [rules file](/docs/rules-file).

## Code index (RAG) <StatusBadge status="inactive" />

The **RAG** switch builds an index of the default branch: which symbols each Python, TypeScript,
JavaScript or Go file defines and which files import each other. Only this structure is stored,
with paths and line numbers, never the code text.

Reviews do not use the index yet, so turning it on changes nothing in a review and adds no cost
today. It keeps itself up to date after pushes and merges to the default branch.

Builds stop at fixed limits, for example a 100 MiB repository archive or 15 minutes of build
time; the status then shows **Error** with the reason. The index is deleted when you switch RAG
off, when the repository leaves the installation, and 30 days after you switched it on. To
rebuild it, switch RAG off and on.

## Dashboard

The dashboard has two sections: **Repositories** and **Runs**. From a repository's settings,
**Review history** opens the runs of that repository.

### Runs

**Runs** lists every pull request that was reviewed or is being reviewed, newest first, with its
repository and [status](/docs/how-it-works#run-statuses). The list updates live.

<RunsListMock />

### Run details

Click a run to open it:

- **Run card**: repository, pull request, commit, branches, model, status, verdict, finding
  counts per severity, timings and the error code if it failed.
- **Stages**: collecting context, model analysis and publishing, with the failed stage marked.
- **Review session**: a log of every step the run took, in order, with its duration. Click a
  step to see what was sent and what came back.
- **Diff and findings**: the diff with findings inline. Filter by file, severity or text, and
  switch between unified and split views.
- **Cancel** for an active run, **Restart** for a finished one. A restart reviews the latest
  commit of the pull request, even if it was reviewed before.
