## When a review starts

A review starts when the pull request has the `ai-review` label, CI on the latest commit has
passed and the repository's **Automatic review** switch is on.

<Callout title="Today the label is needed">
  Despite its name, the **Automatic review** switch only turns reviews on or off for the
  repository. A pull request still needs the `ai-review` label.
</Callout>

<StatusBadge /> Soon the switch will choose the trigger. On: every pull request is reviewed
automatically, without the label. Off: only pull requests with the `ai-review` label.

## New commits

Each commit is reviewed once. A new push stops the review of the old commit and the new commit
is reviewed once CI passes; the label stays. To review the same commit again, click **Restart**
on the run in the dashboard.

## Read the result

| Verdict | When |
| --- | --- |
| `blocking` | At least one `critical` or `high` finding. |
| `attention` | Only `medium` or `low` findings. |
| `clean` | Nothing above `info`. |

Findings go inline on changed lines; the rest are in the review body. The `AI Review` check ends
as neutral, skipped or cancelled and never fails, so do not make it a required check.

## Details

<Accordions>
<Accordion title="CI waiting">

| Setting | Behaviour |
| --- | --- |
| Auto (default) | Waits for checks if the commit has any. With no checks, starts about 2 minutes after the label. |
| Always | Always waits for successful CI. With no CI, the review never starts. |
| Never | Starts right away. |

Check suites must finish as `success`, `neutral` or `skipped`, and commit statuses, if any, must
be `success`. Reviewer looks again whenever a check finishes. The `AI Review` check is not
counted.

</Accordion>
<Accordion title="Label removed, switch off, pull request closed">

- Removing the label stops reviews of later pushes. A run already waiting or working keeps going;
  click **Cancel** on the run to stop it.
- Switching **Automatic review** off stops new runs, and a waiting run is skipped.
- Closing the pull request stops an active run.
- Other labels and events caused by the Reviewer bot are ignored. Older reviews stay on the pull
  request.

</Accordion>
<Accordion title="Run statuses">

Each review attempt is a **run**: `queued`, `running`, `publishing`, then `succeeded`, `failed`,
`cancelled` or `skipped`. Temporary errors are retried automatically. Reasons for skipped and
failed runs are in the [FAQ](/docs/faq#a-run-was-skipped).

</Accordion>
<Accordion title="Findings">

Each finding has a severity (`critical`, `high`, `medium`, `low`, `info`), a category
(`security`, `correctness`, `performance`, `readability`), a title and an explanation.
Findings the model is less sure about, findings outside changed lines and findings over the
comment limit go to the review body. Pure style nits are dropped unless serious. With the
**Verdict** setting on "Request changes", blocking reviews are posted as Request changes.

</Accordion>
<Accordion title="What is not reviewed">

- Lock files and build output, for example `pnpm-lock.yaml`, `go.sum`, `*.min.js` and a top
  level `dist/` folder.
- Binary files and files with more than 20,000 changed lines or over 1 MiB.
- Files that match `review-ignore` in your [rules file](/docs/rules-file).

With more than 3,000 changed lines, Reviewer reviews only the file list: no line comments, and
the dashboard shows no verdict.

</Accordion>
</Accordions>
