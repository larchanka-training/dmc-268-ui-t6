Reviewer is a GitHub App. Add the `ai-review` label to a pull request and, once CI passes,
Reviewer reads the change and posts a GitHub review with inline comments, severity levels,
suggested fixes and a verdict.

## What you get on a pull request

- **A review from the Reviewer bot.** Each finding is an inline comment on the changed line:
  a short title, an explanation and, when it helps, a suggested change you can commit.
- **A summary in the review body**: the verdict, the number of findings per severity and the
  list of checked files. Findings that do not fit on a changed line are listed there too.
- **A check named `AI Review`** that shows progress. It finishes as neutral, skipped or
  cancelled and never fails, so it does not block a merge.
- **A verdict**: `blocking` (critical or high findings), `attention` (medium or low) or `clean`.
  You can choose to post blocking reviews as "Request changes".

## What it reads

- The diff of the pull request.
- The title, description, author, branches, labels and commit messages.
- The root `AGENTS.md` of your repository, if there is one.
- A short summary of your project's conventions that Reviewer writes itself from the file tree
  and up to 10 files of the branch your pull request targets.
- Built-in review guidelines: naming, error handling, complex functions, comments, tests and
  architecture boundaries. Reviewer picks a backend or a frontend set when the repository is
  connected.

## What it does not do

- It does not run your code, tests or build. It only reads text through the GitHub API.
- It does not merge, approve, dismiss old reviews or resolve threads.
- It does not start when a pull request opens. You add the `ai-review` label.
