Add `.review/rules.md` at the root of your repository. It is optional and read from the commit
your pull request is based on, so a change counts only after it is merged. The other review
options are in the dashboard, see [Repository settings](/docs/features#repository-settings).

<RulesSnippet />

## Ignore files

Today the part that works is one `review-ignore` block: path masks, one per line. Matching files
are never sent to the model.

````markdown title=".review/rules.md"
```review-ignore
generated/**
dist/**
**/*.min.js
```
````

| Mask | Matches |
| --- | --- |
| `generated/**` | Everything in `generated/` at the root. |
| `**/*.py` | Any `.py` file at any depth. |
| `src/*` | `src/a.ts`, but not `src/a/b.ts`. |

<Accordions>
<Accordion title="Mask rules">

- A mask matches the whole path from the root and is case sensitive.
- `*` matches within one folder or file name. `**` stands alone between slashes and matches any
  number of folders, including none. Use `generated/**` for a folder, not `generated/`.
- No `!`, `?`, `[ ]`, `{ }` or backslash. `#` is a normal character, not a comment.
- One block, at the top level of the file, closed. Up to 256 lines; each mask up to 256 bytes.
- If every changed file is ignored, the run is skipped.

</Accordion>
</Accordions>

## Errors fail the run

Reviewer checks `.review/rules.md` and the root `AGENTS.md` on every run. If one is broken, the
run fails with a `policy_` code and the `AI Review` check names the file, line and problem. The
repository settings page shows the same under **Review rules**.

<Accordions>
<Accordion title="Common errors">

| Code | Problem |
| --- | --- |
| `policy_document_too_large` | The file is over 64 KiB. |
| `policy_document_decode_error` | The file is not valid UTF-8. |
| `policy_document_type_unsupported` | A symlink, submodule or LFS pointer, not a regular file. |
| `policy_ignore_pattern_invalid` | A mask uses syntax that is not allowed. |
| `policy_ignore_block_unclosed` | The `review-ignore` block is not closed. |

</Accordion>
</Accordions>

## Your rules for the model <StatusBadge />

The rest of the file is for rules in plain words, under headings like `# Security` or
`# Style`. Today this text is checked but not sent to the model, so it has no effect yet.

<Accordions>
<Accordion title="Example, shortened from the format spec">

````markdown title=".review/rules.md"
# Security

SQL queries with user input must be parameterized.

## TypeScript

In TypeScript files (`**/*.ts`, `**/*.tsx`), treat the result of an external JSON
API as `unknown` until its shape is checked.

# Performance

When processing the list of orders, do not run a separate database query per order.

# Style

Duplicated test setup is fine in tests when it helps readability.

# Ignore

```review-ignore
generated/**
dist/**
**/*.min.js
```
````

Headings are for people; names and order are free. Paths in the text only hint where a rule
applies. Both files together must fit in 12,000 tokens.

</Accordion>
</Accordions>
