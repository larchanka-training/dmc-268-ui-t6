---
title: Connect Bitbucket Cloud
description: Connect a repository, configure its webhook, and read its reviews.
icon: GitPullRequest
---

Use a Bitbucket Cloud repository that you can access, including a private one. You also need membership in the portal workspace where you want it to appear. Repository webhooks are configured manually, so you need permission to manage that repository's webhooks in Bitbucket.

<Steps>
<Step>

### Create an API token

Create a scoped [Atlassian API token](https://support.atlassian.com/bitbucket-cloud/docs/using-api-tokens/) for the Bitbucket workspace with **Repositories: Read** (`read:repository:bitbucket`) and **Pull requests: Read** (`read:pullrequest:bitbucket`). The portal stores this token encrypted and uses it to read the repository and publish review comments and commit status. Keep the token out of chat, screenshots and repository files. The manual webhook flow does not need webhook API scopes.

</Step>
<Step>

### Connect the repository

Open <AppLink path="/repositories">**Repositories**</AppLink> and choose the **portal workspace** explicitly in the Bitbucket Cloud panel. Enter the Bitbucket workspace slug and API token, then choose **Find repositories** («Найти репозитории»). Select the repository, including a private one, and choose **Connect** («Подключить»). The repository appears in the common list for members of that portal workspace.

</Step>
<Step>

### Configure the repository webhook

The portal shows a webhook URL, event list and secret **once**. In that repository's Bitbucket settings, add a webhook with the shown URL and secret. Subscribe to `repo:push`, `pullrequest:created` and `pullrequest:updated`. Keep the secret in Bitbucket's webhook settings or a protected secret store; it is not available from the portal later. The portal shows **Awaiting webhook** until it receives the first valid signed delivery for that repository, then **Webhook active**.

</Step>
<Step>

### Review and disconnect

Open a pull request, then follow the review in <AppLink path="/runs">**Runs**</AppLink>. Findings appear as inline Bitbucket comments, with one summary and a commit status for the reviewed head. Suggested patches currently appear as **comment text for manual application**; the public REST comment contract has not established a native, one-click suggestion field. A real pull request capability check is still pending.

To stop one repository, choose **Disconnect** («Отключить») on its connection and remove that repository's webhook in Bitbucket. Other repositories under the same connection remain active. Replacing the shared API token is an explicit **Update API token** action. If you rotate a repository's webhook secret, update that webhook in Bitbucket using the new one-time secret.

</Step>
</Steps>
